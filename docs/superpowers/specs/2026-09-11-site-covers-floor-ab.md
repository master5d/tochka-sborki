**Дата:** 2026-09-11. **Статус:** черновик на утверждение владельца.
**Исправляет:** решение из `2026-09-08-quest-home-design.md` («старый `home-page.tsx` удаляется,

## Правила владельца (дословно по смыслу, 2026-09-11)

1. Трендовая обложка выглядит **только как витрина**. Переключателя у посетителя нет.
2. Откат или смена обложки (трендовой или любой другой) — **только на бекэнде и только по
   команде владельца**, после того как финальный дизайн утверждён.
3. Вся работа до финального дизайна идёт **только на превью**. На проде это допустимо как
   A/B-тест.

Обложка — не клон тренда, а авторский синтез владельца, вдохновлённый трендом: ручные решения в
теме — осознанный выбор и часть произведения, отдельным слоем «отклонений» они не выносятся и
долгом не считаются. Модуль трендов даёт вход (обложка тренда из записей Adweek `class:trend`:
палитра, типографика, срок `until`), сайт ссылается на неё как на источник вдохновения.
Шлифовка модуля на сайте — через замеры на превью (вайб-чек к центроиду тренда, контраст,
fps), а не через подгонку CSS под машинную обложку.

## Сборка

Статический экспорт собирает **обе** главные:
- `/` и `/en/` — пол (то, что видит поисковик и посетитель по умолчанию);
- `/_cover/trend-adweek-2026-09/` и `/en/_cover/…/` — обложка, `noindex`, ни одной ссылки на неё.

Реестр обложек — `hub/lib/covers.ts` (`id → {home, themeCss}`), пол — всегда элемент реестра.

## Раздача (бекэнд, без переключателя)

Pages Function `hub/functions/_middleware.ts` на `/` и `/en/`:
- читает конфиг из KV `SITE_COVER`: `{ active: 'floor' | '<id>', ab: { cover: '<id>', share: 0–100 } | null }`;
- `active` ≠ `floor` → отдаёт HTML обложки по адресу `/` (rewrite через `env.ASSETS.fetch`);
- `ab` задан → доля посетителей получает обложку, вариант закреплён cookie `mc_variant`
  (посетитель не прыгает между дизайнами), канонический URL остаётся `/`;
- KV недоступен или конфиг битый → **пол** (отказ в безопасную сторону);
- заголовок `x-mc-cover` в ответе — для проверки, какой вариант отдан.

Метрика A/B: вариант уходит в PostHog как свойство события, если ключ задан (сейчас
dark-ship); без ключа — только логи Pages.

## Команды владельца (исполняю я, только по его слову)

`hub/scripts/cover.ps1`:
- `status` — что активно, какая доля в A/B, какие обложки собраны;
- `ab <id> <share>` — запустить или изменить A/B;
- `promote <id>` — утверждённая обложка становится активной для всех;
- `rollback` — пол для всех, A/B снят.

Каждая команда пишет KV через wrangler (без пересборки, действует за секунды) и печатает
состояние до/после. Сверх того остаётся мгновенный откат деплоя в Cloudflare Pages.

## Превью

Ветки деплоятся на `*.mamaev-coach-hub.pages.dev`; на превью middleware отдаёт на `/` ту
обложку, над которой идёт работа (переменная окружения превью, не KV прода). Итерации дизайна
живут только там.

## Переход с нынешнего состояния

Прод сейчас отдаёт квест на `/` (`044d725`) — это работа до утверждения финального дизайна,
то есть против правила 3. После выката этой схемы на `/` встаёт пол, обложка — только по
A/B-доле, которую назовёт владелец (по умолчанию 0 %).

## Проверки

- тест реестра: пол есть, у каждой обложки есть главная и тема, id совпадают с файлами;
- тест middleware (чистая функция выбора варианта): битый/пустой конфиг → пол; доля 0 → пол;
  доля 100 → обложка; cookie держит вариант; `_cover` страницы несут `noindex`;
- гвард «нет переключателя»: в собранном HTML пола и обложки нет ссылок на `/_cover/`;
- смок после деплоя: `x-mc-cover` для `/` при каждом состоянии KV;
- у обложки в реестре указан провенанс (id тренда), JSON тренда существует.

## Вне объёма

Мультиобложки вкуса (`taste-*`), автоматическое продвижение победителя A/B, SEO-эксперименты.
